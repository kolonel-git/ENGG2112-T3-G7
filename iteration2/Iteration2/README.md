# Iteration2: turbine alarm prediction pipeline

This folder contains the complete workflow from raw turbine CSV files to time-series plots and alarm-prediction models. Paths below are relative to **this Iteration2 folder**, not the outer Git repository.

## 1. Set up Python and the notebook kernel

On Windows, install Python 3.10 or newer. Open a PowerShell terminal in this folder and run:

```powershell
.\setup_environment.ps1
```

This creates or updates `.venv` and installs [requirements.txt](requirements.txt). In VS Code, install/enable its Python and Jupyter extensions, open a notebook, and select this folder's `.venv\Scripts\python.exe` as the kernel. If the folder was copied from another computer/location, recreate the virtual environment here rather than relying on a copied `.venv`.

For each notebook, edit its settings and use **Run All**. Run from this folder or a notebook's own subfolder so workspace discovery can find this project. If changing alarm targets or training settings in an existing session, **Restart Kernel**, then Run All to avoid mixing old models with new labels.

## 2. Put your data in the appropriate location

### Starting with raw CSV files

Put each year's original CSV files in its own folder:

```text
Iteration2/
  Data/
    raw/
      2016/
        tblSCTurbine_2016_01.csv
        tblSCTurPress_2016_01.csv
        tblSCTurTemp_2016_01.csv
        tblAlarmLog_2016_01.csv
        ...other monthly files...
      2017/
        ...monthly CSV files for 2017...
```

Each selected year needs files for all four table types above. Keep their original column headers and filenames. The export notebook searches for `*_<year>_*.csv`. Daily-summary files are not needed for this pipeline. The notebook calls the input folder `Data/Raw`; Windows treats `Raw` and `raw` as the same directory. On a case-sensitive system, set `RAW_ROOT` to match the actual folder name.

### Already have prepared data? Start here

You do **not** need to regenerate every stage if you already have its output.

| Files you already have | Where to put them | First step to run |
|---|---|---|
| Original monthly CSVs | `Data/raw/<year>/` | Stage 1: export |
| Workbooks generated by this pipeline, named `turbines_<year>.xlsx` | `Data/Interim/turbine_exports/` | Stage 2: Parquet setup |
| Source Parquet pairs: `sensors.parquet` and `alarms.parquet` | `Data_Parquets/<year>/Station_<ID>/` | Stage 3: preprocessing |
| Processed 10-minute `data.parquet` files | `Data_Parquets_10min/<year>/Station_<ID>/` | Stage 4: plots, or Stage 5: training |

Prepared files must use this pipeline's schema; renaming an arbitrary Excel/Parquet file is not enough. Source and processed stages also create `source.json` metadata files; retain these when copying complete output folders. Older source folders named `turbines_<year>` are accepted, but plain year names are preferred.

```text
Data/Interim/turbine_exports/turbines_2016.xlsx
Data_Parquets/2016/Station_2304511/sensors.parquet
Data_Parquets/2016/Station_2304511/alarms.parquet
Data_Parquets_10min/2016/Station_2304511/data.parquet
```

The project ignores large datasets and generated model files in Git. Someone cloning the repository must supply their own data or copy the prepared data folders separately.

## 3. Run the pipeline in order

### Stage 1: export raw data to yearly Excel workbooks

Run [01_export_yearly_turbine_scada.ipynb](notebooks/01_data_export/01_export_yearly_turbine_scada.ipynb).

Set the years you actually have, for example:

```python
YEARS = [2016, 2017, 2018]
```

Check `RAW_ROOT` and `OUTPUT_DIR`, then Run All. It creates one workbook and `.report.json` sidecar per year in `Data/Interim/turbine_exports/`, with a sheet for each turbine. It preserves source CSVs. Sensor records with the same table, turbine and timestamp use the last record read; alarm events are retained, including duplicates. Re-running replaces the configured yearly outputs.

The [optional 10-minute Excel export](notebooks/01_data_export/02_optional_export_10min_alarm_scada.ipynb) is a separate alternative for inspection. It is **not required** for the Parquet or training workflow below; use the primary export above for Stage 2.

### Stage 2: convert the exported workbooks to source Parquet

Run [01_setup_yearly_parquets.ipynb](notebooks/02_parquet_setup/01_setup_yearly_parquets.ipynb).

```python
YEARS = [2016, 2017, 2018]
TURBINE_IDS = None  # All turbines; or ['2304511'].
REBUILD = False
```

Set `YEARS` to workbooks that already exist. This creates `sensors.parquet`, `alarms.parquet` and `source.json` per turbine in `Data_Parquets/<year>/Station_<ID>/`. Initial Excel conversion can take several minutes. Current outputs are reused when possible; `REBUILD = True` forces reconversion (set it back to False afterwards).

### Stage 3: preprocess to a regular 10-minute timeline

Run [01_preprocess_10min_parquets.ipynb](notebooks/03_preprocessing/01_preprocess_10min_parquets.ipynb).

```python
YEARS = None        # All prepared years; or [2016, 2017].
TURBINE_IDS = None  # All prepared turbines; or ['2304511'].
REBUILD = False
```

This creates `Data_Parquets_10min/<year>/Station_<ID>/data.parquet`. Source Parquet files are preserved. Each year gets a full 10-minute grid; the timestamp marks the start of `[t, t + 10 minutes)`. Missing sensor intervals remain blank and have `sensorObserved = False`; no interpolation is performed. Off-grid sensor timestamps require an explicit alignment decision and stop preprocessing.

Important output columns:

| Column | Meaning |
|---|---|
| `wtc_*` | Sensor readings |
| `sensorObserved` | A real sensor observation existed at this interval |
| `alarmOccurred` | Any alarm code started during the interval |
| `selectedAlarmOccurred` | At least one code from `SELECTED_ALARM_CODES` started |
| `triggeredAlarmCodes`, `triggeredAlarmCounts`, `alarmTriggerCount` | All starting codes, per-code counts and total starts |
| `selectedTriggeredAlarmCodes`, `selectedTriggeredAlarmCounts`, `selectedAlarmTriggerCount` | The same fields restricted to selected codes |
| `alarmOn`, `activeAlarmCodes` | Whether any alarm was active during the interval, and its codes |
| `alarmEvents` | Original event timing retained as JSON for labels and auditing |

The default selected preprocessing codes are 3130, 8000, 8235 and 10105; edit `SELECTED_ALARM_CODES` if needed. Other alarm records are **not removed**. Training notebooks use their own `ALARM_CODES`, so the icing group can still use codes outside that selected preprocessing list. Unknown/zero event durations flag the start interval only. Identical alarm records are retained and counted separately.

After adding/changing raw data, rerun Stages 1, 2 and 3 for the affected years before plotting or retraining.

### Stage 4: generate feature plots

Choose any notebook in [04_data_visualisation](notebooks/04_data_visualisation/):

- [01_plot_turbine_feature.ipynb](notebooks/04_data_visualisation/01_plot_turbine_feature.ipynb): one chosen feature, with editable durations.
- [02_all_features_day.ipynb](notebooks/04_data_visualisation/02_all_features_day.ipynb): daily views.
- [03_all_features_week.ipynb](notebooks/04_data_visualisation/03_all_features_week.ipynb): weekly views.
- [04_all_features_month.ipynb](notebooks/04_data_visualisation/04_all_features_month.ipynb): monthly views.
- [05_all_features_year.ipynb](notebooks/04_data_visualisation/05_all_features_year.ipynb): yearly views.

Set `YEAR`, `TURBINE_ID`, and the date settings (`WINDOW_START` or `START_DATE`/`END_DATE`, depending on the notebook), then Run All. For the single-feature view, set `FEATURE` too. All-feature views have a separate plotting cell per sensor. Alarm filters and legends are controlled in notebook settings. Empty features are shown/reported without inventing readings.

After the first load, use the **Fast date change and redraw** cell in the all-feature notebooks to inspect another period without reopening data files. Set `VIEW_START`, `VIEW_DURATION` and, optionally, `VIEW_FEATURES`. The alarm-count cell counts recorded starts in the selected period using the current plot filters; rerun it after changing dates.

Plots appear in notebook outputs. You can run any view independently; daily plots are not prerequisites for weekly/monthly/yearly plots or model training.

### Stage 5: train models and generate evaluation plots

Choose the target folder in [05_model_training](notebooks/05_model_training/):

| Folder | Alarm target |
|---|---|
| [pitch_lubrication_3130](notebooks/05_model_training/pitch_lubrication_3130/) | 3130: pitch lubrication |
| [untwisting_cables_10105](notebooks/05_model_training/untwisting_cables_10105/) | 10105: stopped, untwisting cables |
| [icing_8230_8234_8235_8236](notebooks/05_model_training/icing_8230_8234_8235_8236/) | Any of 8230, 8234, 8235 or 8236 |

Then choose a horizon folder: `01_horizon_10min`, `02_horizon_1hour`, `03_horizon_6hours`, `04_horizon_1day`, or `05_horizon_1week`.

Each contains:

- `01_train_all_features.ipynb`: all sensor features.
- `02_train_selected_features.ipynb`: edit `SELECTED_FEATURES` to choose sensors; a feature catalogue is provided.
- `03_train_selected_features_variant.ipynb`: alternate copy. With identical settings it duplicates the selected-feature experiment and writes to the same output folder; you do not need to run both.

Check `ALARM_CODES`, `TARGET_NAME`, `TURBINE_IDS`, `HORIZON`, `TRAIN_END` and `VALIDATION_END`, then Restart Kernel and Run All. For example, `TURBINE_IDS = ['2304511']` trains only that turbine; add other IDs explicitly to include them.

All horizons use only the **preceding one hour** of sensor readings and issue predictions every **10 minutes**. The horizon is the future interval being predicted, not the input length. A window is positive if any selected alarm starts within that horizon. Models exclude windows while the target group is already active. Sensor fields alone are predictors; alarm flags/counts are not inputs.

The default chronological split fits models on available pre-2023 data, chooses thresholds on 2023 validation data, and tests on 2024 onward. Boundary windows are purged using the lookback/horizon. A split needs both positive and negative examples. Each notebook trains independently: you do not need to train the 10-minute version before the 1-day version, or train one alarm target before another.

Models: constant prevalence, random-weight score, logistic regression, LightGBM and random forest. Thresholds maximise validation F1 (constant baseline uses 0.5). Evaluation includes precision, recall, F1/F2, AP, ROC-AUC, confusion matrices, precision-recall curves and prediction timelines. Training-history scores are in-sample. Longer horizons can label many overlapping windows positive for one event; window counts are not counts of independent alarms.

## 4. Find and reuse outputs

- Export workbooks: `Data/Interim/turbine_exports/`.
- Source Parquet: `Data_Parquets/`.
- Model/plot input data: `Data_Parquets_10min/`.
- Training results: `reports/alarm_<target>_<horizon-in-minutes>min_aligned/`, or a `...min_selected_<selection-id>/` folder for chosen features.

Training folders include `metrics.csv`, `precision_recall.png`, `confusion_matrices.png`, `trained_models.joblib`, `configuration.json` and `test_predictions.parquet`. Additional timeline plots appear in notebook outputs. Identical settings can overwrite the same result directory, so copy/rename a result directory before a run if you want to retain that experiment. Existing report files alone do not populate a fresh kernel; training notebooks run their training cells again when you choose Run All.

To review another date with models already fitted in the current kernel, rerun the prediction-timeline cell with a new start/duration. To change target codes, sensors, turbines or horizon, retrain; an old fitted model does not automatically change its target.

## 5. Common problems

- **Missing yearly workbook:** Stage 2 requests a year not yet exported. Run Stage 1 or correct `YEARS`/`EXCEL_FOLDER`.
- **Missing processed Parquet:** run Stage 3 for the selected year/turbine, or copy its complete processed folder into the layout above.
- **NameError for a data/model variable:** earlier cells were not run in this kernel. Restart Kernel and Run All.
- **A split needs both classes:** no positive alarms (or no eligible rows) exist for that target/turbine/period. Inspect event counts and source coverage; do not bypass the check or randomly mix dates.
- **Blank sensor plots:** the source may not contain that sensor in the selected year, or the date range has no observations. Missing readings remain blank in processed files.
- **Slow first run:** Excel conversion is done in preparation, not plotting/training. With processed data already available, skip directly to Stage 4 or 5.

For notebook navigation, see [notebooks/README.md](notebooks/README.md) and the [old-to-new notebook locations](notebooks/NOTEBOOK_LOCATIONS.md). Supporting modules in `notebooks/shared/` are imported automatically; they are not separate pipeline steps.


## All-turbine chronological cross-validation

For the next development stage, use [06_all_turbine_cross_validation](notebooks/06_all_turbine_cross_validation/README.md) and its [6-hour 8200-family notebook](notebooks/06_all_turbine_cross_validation/01_cv_8200_family_all_turbines_6hour.ipynb). It requires the processed files from Stage 3, not the earlier single-turbine models.

It pools all eligible sensor turbines in available 2016–2023 data, with independent calibration and evaluation years in each fold, and then freezes final models after a development-only refit. Default training keeps all positive windows and a weighted negative sample from every turbine-year; set MAX_TRAIN_NEGATIVES to None to use all rows if resources permit. Event-level and per-turbine reports supplement window metrics. The CV target now uses only 8230, 8234, 8235 and 8236, matching the four-code icing group. Earlier broad 8200–8299 reports are separate historical experiments.

The 2024–2025 test step is off by default (`RUN_RESERVED_TEST = False`), including during Run All. Enable it only after choosing and freezing the development configuration. These years were already examined in previous experiments, so they are not historically untouched. Full all-turbine CV can take substantially longer than a single-turbine run.


## View saved cross-validation evaluation

Open [evaluate_cross_validation_results.ipynb](evaluate_cross_validation_results.ipynb) in this folder and Run All. It automatically selects the most recently completed CV result set, or set RUN_ID to choose one. It displays fold/candidate metrics, per-turbine results, PR curves and confusion matrices without retraining, changing thresholds or opening reserved test data. Set PLOT_PRECISION_RECALL to False for CSV-only review if needed.
