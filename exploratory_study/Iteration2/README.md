# Iteration 2: start here

This is the active project. All paths in this guide are relative to this folder.

**First notebook:** [00_START_HERE.ipynb](00_START_HERE.ipynb). Its cells only check available data and show where to start; they do not train or convert files.

## 1. Set up once

Open `Iteration2.code-workspace` from the repository root, or open this folder directly in VS Code. Install the Python and Jupyter extensions. In a PowerShell terminal in this folder:

```powershell
.\setup_environment.ps1
```

Requires Python 3.10 or newer. Select this folder's `.venv/Scripts/python.exe` as the notebook kernel. Dependencies, including XGBoost, are in [requirements.txt](requirements.txt). A copied virtual environment should be recreated for the new machine.

## 2. Choose your starting point

| What you already have | Put it here | Start at |
|---|---|---|
| Original monthly CSV files | `Data/Raw/<year>/` | Stage 1 |
| Yearly `turbines_<year>.xlsx` exports | `Data/Interim/turbine_exports/` | Stage 2 |
| `sensors.parquet`, `alarms.parquet`, `source.json` | `Data_Parquets/<year>/Station_<ID>/` | Stage 3 |
| Processed `data.parquet` files and metadata | `Data_Parquets_10min/<year>/Station_<ID>/` | Stage 4 or 5 |

Use files generated by this pipeline; arbitrary spreadsheets do not have the required schema. Preserve metadata sidecars when copying datasets. The processed Parquets are configured for Git LFS. With Git LFS installed, run `git lfs install` and `git lfs pull` from the repository; confirm actual Parquets arrived using Start Here. Raw CSVs and Excel files must be supplied separately if needed.

Edit settings, then **Restart Kernel → Run All** in each selected notebook. Stage numbers describe dependencies, not a requirement to run every notebook. Different plots, alarm groups, feature variants and horizons are independent choices. Plotting is not required before training. Python modules under `notebooks/shared/` are imported automatically.

For raw input, each selected year's folder needs the monthly `tblSCTurbine`, `tblSCTurPress`, `tblSCTurTemp` and `tblAlarmLog` CSVs with original names and headers. Check `RAW_ROOT`, `OUTPUT_DIR` and `YEARS` in Stage 1. The optional second Excel export is for inspection and is not required. Before Stages 1–3, choose the years you actually need; current training needs **2016, 2017, 2018, 2020, 2021**. Windows ignores `Raw`/`raw` case; other systems require matching folder case.

Initial Excel conversion is slow. Once processed Parquets exist, skip Stages 1–3 for repeated training. Preprocessing retains all alarm records and sensor missingness; selected-alarm flags do not restrict training targets.

## 4. Recommended first training run

Open [all alarms → 10 minutes → all features](notebooks/05_model_training/all_alarms/01_horizon_10min/01_train_all_features.ipynb). To focus on faults instead of operational alarms, choose an alarm-specific group from the training guide.

Current Stage 5 defaults:

- Turbines **2304510–2304514**, pooled for fitting with separate per-turbine histories.
- Training **2016–2018**, validation/threshold selection **2020**, test **2021**. Only those five years are loaded.
- **Two hours** of past sensor readings: 12 previous ten-minute observations, excluding the current reading. Rolling mean, standard deviation, minimum and maximum are model inputs.
- Binary target: a **new target alarm start** within the configured future horizon. Already-active target alarm windows are excluded. Missing histories and split-boundary windows are excluded.
- Models: constant prevalence, random-weight baseline, lightweight logistic regression, random forest, LightGBM and XGBoost.
- Validation chooses F1 thresholds; test applies fixed thresholds. Metrics include precision, recall, F1/F2, AP, ROC-AUC and confusion matrices. The 10/20/30-minute all-feature notebooks also include the detailed binary summary and ROC curves.

Running every training notebook is unnecessary and can take a long time. Start with one, then change target or horizon deliberately. More frequent operational alarms may improve apparent metrics without improving fault prediction. Historical evaluation years have already been inspected; these are exploratory comparisons.

## 5. Find results

Each training notebook prints its output directory under `reports/`. Compact names such as `all_alarms_30m_all_<hash>` avoid Windows path-length problems. Read `configuration.json` for exact settings.

| File | Contents |

| `binary_classification_metrics.csv` | Additional binary summary, where available |
| `precision_recall.png`, `confusion_matrices.png`, `roc_curves.png` | Saved evaluation figures; ROC figure where available |
| `trained_models.joblib` | Fitted models and preprocessing |
| `test_predictions.parquet`, `binary_predictions.parquet` | Scores/decisions; binary file where available |

[CONCLUSIONS.md](CONCLUSIONS.md) describes historical runs; it is not automatically updated when a notebook reruns. CV has separate settings, reports and results: its six-hour experiment uses all eligible turbines, development 2016–2023, and disabled reserved testing on 2024–2025. Do not mix its results with the five-turbine experiment.

## Troubleshooting and navigation

- Missing file: check the starting-point table and requested years; do not rerun raw conversion if processed data already exists.
- `NameError`: restart the kernel and Run All from the top.
- A split needs both classes: inspect its positive counts; do not bypass the check or randomly shuffle time.
- Slow training: choose one notebook, inspect printed timings, reduce `TREE_ESTIMATORS`, or disable optional logistic regression. These are new experiment settings.
- Git: large ZIP archives and virtual environments do not belong in commits. Processed Parquets use LFS. Keep report paths compact.
