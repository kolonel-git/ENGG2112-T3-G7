## 2. Objectives and deliverables

| Objective | Deliverable | Acceptance |
|-----------|-------------|------------|
| O1 degradation indicator | Normal-behaviour models (ridge, LightGBM), daily residual indicator per turbine, plots against fault episodes | Indicator computed from train-only models; behaviour before episodes reported with counts |
| O2 failure/downtime prediction | Baselines and class-weighted LightGBM for targets A and B, evaluated on the test years | PR-AUC, recall at 1 false alarm per turbine-month and median lead time with turbine-bootstrap intervals; every number reproducible from `configs/protocol.yaml` |
| O3 robustness | Leave-one-turbine-out, missing-sensor, year-shift and upgrade analyses | Table of metric change per stress test with positive counts |
| Explainability | SHAP for LightGBM, residual attribution for the normal-behaviour model | Stable top features across folds, written up as attribution, not causation |
| Report | Final report with ethics section, figures and tables generated by scripts | Every figure and table traceable to a script and config; no invented numbers or references |

- **Features** (Revael): daily aggregates, 7-day windows, alarm-count features, operating-state fractions. Output: `src/wt_predmaint/features/`.

### Wk4 Main models

### Wk5 Robustness and SHAP

## 4. Dependencies

- Labels need the cleaning layer and the `tblDailySummary` loader; the harness needs labels only for its integration test.
- Normal-behaviour residual features must be computed before the O2 feature table; both use train-year fits only.
- Upgrade analysis needs `Hill_of_Towie_AeroUp_install_dates.csv`; interpreting `TimeErr` needs the data dictionary; both are Zenodo metadata files not yet in the repo.

## 5. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| `TimeErr` meaning unverified | Cross-check against SCADA-derived stops (target B); get the data dictionary; report both targets |
| Few events per fold, especially in leave-one-turbine-out | Always report positive counts; turbine bootstrap; merge folds or group CV if counts are too small |
| Cross-year drift (hydraulic pressure steps, bearing temperature drift) | Time-based split; year-shift stress test; per-year feature checks |
| No measured active power | Rpm-vs-wind curve proxy and daily energy, documented deviation (D-011) |
| Possible anemometer faults on a few turbine-years | Flag and test with and without those turbine-years |
| Data leakage | Train-only fits, window features end at t, leakage test in the suite |
| Undocumented alarm codes (21% of the log) | Not used as targets; tested only as a discovery aid for stops |
| Time | Gates G1 to G5; optional items (autoencoder, extra tuning) are cut first |

## 6. Working agreement

- One branch per task named `owner/short-topic`, small PRs, one reviewer, no direct pushes to `main` (see `CONTRIBUTING.md`).
- Every decision that changes the plan goes in `docs/DECISIONS.md` the same day with an ID; configs change only together with their decision entry.
- Never commit data. Never invent results or references.

## 7. Known limitations to state in the report

- No measured active power or failure/maintenance records in the open data; "degradation" and "failure" are inferred from fault time and SCADA behaviour.
- Alarm descriptions exist for only 12 codes; most of the log is undocumented.
- 2019 temperature and pressure tables are missing; 2022-08, 2022-09 and 2025-09 are outage months.
